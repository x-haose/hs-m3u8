# ADR-0003：仓库布局与从 0.1.x 迁移

- 状态：已采纳
- 日期：2026-10-09

## 决定

1. Rust 重写放在本仓库（x-haose/hs-m3u8），不新开仓库：GitHub 仓库、issue 历史与 PyPI 包名 `hs-m3u8` 延续。
2. 仓库改为 Cargo workspace，目录见架构设计第 2 节。
3. 重写在长期分支 `rewrite/rust` 上进行；核心与 Python 绑定达到下列条件后合入 master，Python 0.1.x 代码只保留在 git 历史中：
   - 覆盖 0.1.x 全部能力：自定义请求头、自定义 key、m3u8 文本/请求/key 三类回调、断点续传、保留 HLS 目录；
   - 修掉 0.1.x 审查出的全部问题；
   - 支持音视频分流；
   - macOS、Windows、Linux 三平台 CI 通过。
4. Python 绑定以 `hs-m3u8` 1.0.0 发布，最低 Python 3.11，API 不兼容 0.1.x，README 提供迁移说明。
5. 桌面应用在 master 上继续开发，与 Python 包分开发版。

## 考虑过的方案

- 新开仓库：历史干净，但丢失仓库与包名的延续，用户需要换包名。
- 在 master 上直接改：重写期间 master 不可发布 0.1.x 修复。

## 后果

- 重写期间 0.1.x 的严重问题修复从 master 发 0.1.x 补丁版本。
- 仓库历史里的 ffmpeg 压缩包（约 115 MB）使克隆偏慢；清理需要改写历史并强制推送，是否清理由仓库所有者另行决定。
